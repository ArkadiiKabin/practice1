## 3. Задание 1. Операции с массивом

### 3.1. Контракты

| Функция | Входные данные | Результат | Ограничения |
|---|---|---|---|
| `max_element_value(a, n)` | Массив целых чисел | Наибольший элемент | `n >= 1` |
| `sum_elements(a, n)` | Массив целых чисел | Сумма элементов типа `long long` | `n >= 0`; для пустого массива результат `0` |
| `contains(a, n, x)` | Массив и искомое `x` | `true`, если элемент найден, иначе `false` | `n >= 0` |

Ограничения задания: `0 <= n <= 100000`, значения элементов и `x` находятся в диапазоне `[-10^9, 10^9]`. Функция максимума не вызывается для пустого массива.

### 3.2. Описание алгоритмов

**Поиск максимума.** Начальное значение максимума берётся из `a[0]`, затем остальные элементы по очереди сравниваются с текущим максимумом. Инициализация нулём была бы ошибочной: если все элементы отрицательные, функция могла бы вернуть `0`, которого в массиве нет.

**Сумма.** Переменная `sum` инициализируется нулём, после чего к ней последовательно прибавляется каждый элемент. Используется `long long`, чтобы избежать переполнения `int` при допустимых ограничениях.

**Поиск элемента.** Массив просматривается слева направо. При первом совпадении возвращается `true`; если проход завершился без совпадений, возвращается `false`.

### 3.3. Сложность

Пусть `n` — число элементов.

| Функция | Число основных операций | Лучший случай | Худший случай | Дополнительная память |
|---|---|---|---|---|
| Максимум | `n - 1` сравнений | `Θ(n)` | `Θ(n)` | `Θ(1)` |
| Сумма | `n` сложений | `Θ(n)` | `Θ(n)` | `Θ(1)` |
| `contains` | От 1 до `n` сравнений при `n > 0` | `Θ(1)` | `Θ(n)` | `Θ(1)` |

Для максимума и суммы требуется обработать каждый элемент, поэтому лучший и худший случаи имеют линейный порядок. Для поиска элемента лучший случай — совпадение в первой позиции; худший — элемент отсутствует либо находится в конце.

### 3.4. Тесты

В таблице указаны ожидаемые результаты по условию. Фактический результат необходимо подтвердить запуском программы; значения не следует считать измеренными только на основании описания алгоритма.

| Массив | Операция | Ожидаемый результат |
|---|---|---|
| `[]` | Сумма | `0` |
| `[]` | `contains(5)` | `false` |
| `[5]` | Максимум | `5` |
| `[5]` | Сумма | `5` |
| `[5]` | `contains(5)` | `true` |
| `[-8, -3, -10]` | Максимум | `-3` |
| `[-8, -3, -10]` | Сумма | `-21` |
| `[-8, -3, -10]` | `contains(-3)` | `true` |
| `[4, 7, 11]` | Максимум | `11` |
| `[4, 7, 11]` | Сумма | `22` |
| `[4, 7, 11]` | `contains(6)` | `false` |
| `[7, 7, 9]` | Максимум | `9` |
| `[7, 7, 9]` | Сумма | `23` |
| `[7, 7, 9]` | `contains(7)` | `true` |

Дополнительные граничные проверки: массив из одного отрицательного числа `[-42]` (максимум `-42`, сумма `-42`); поиск совпадения в последней позиции; поиск отсутствующего значения. В фактическом отчёте после запуска следует добавить столбец «Фактический результат» и отметить прохождение тестов.

## 4. Задание 2. Сравнение сортировок

### 4.1. Контракт

На вход подаётся массив длины `0 <= n <= 2000` со значениями от `-10000` до `10000`. Результат — тот же массив, отсортированный по неубыванию. Должны корректно обрабатываться пустой массив, массив из одного элемента и повторяющиеся значения.

### 4.2. Алгоритмы

**Пузырьковая сортировка с досрочным завершением.** На каждом проходе сравниваются соседние элементы; если они расположены неправильно, выполняется обмен. Если за полный проход не было ни одного обмена, массив уже отсортирован и алгоритм завершает работу.

**Сортировка вставками.** Каждый очередной элемент сохраняется во временной переменной `key`. Более крупные элементы отсортированной части сдвигаются вправо, после чего `key` записывается на освободившееся место.

### 4.3. Сложность

| Алгоритм | Лучший случай | Средний/худший случай | Дополнительная память |
|---|---|---|---|
| Пузырьковая с досрочным завершением | `Θ(n)` сравнений на уже отсортированном массиве | `Θ(n²)` | `Θ(1)` |
| Вставками | `Θ(n)` сравнений на уже отсортированном массиве | `Θ(n²)` | `Θ(1)` |

Оба алгоритма выполняются на месте и не требуют дополнительного массива для сортировки. Однако количество операций отличается. На уже отсортированном входе пузырьковая сортировка делает один проход и останавливается. Сортировка вставками также работает за линейное время, но для каждого элемента выполняет запись `key` обратно в массив, даже если сдвигов не было. На убывающем массиве обе сортировки выполняют квадратичное число операций.

Счётчик сравнений должен учитывать только сравнения значений элементов. Счётчик записей должен учитывать присваивания в элементы массива; запись в локальную переменную `key` не учитывается, а обычный обмен в пузырьковой сортировке считается двумя записями.

## 5. Задание 3. Вторая лексикографически наибольшая различная строка

### 5.1. Контракт

Дан массив из `n` непустых строк, содержащих строчные латинские буквы. Необходимо вывести вторую по величине различную строку в лексикографическом порядке. Повторения не занимают отдельные позиции. Если различных строк меньше двух, результат — `NONE`.

### 5.2. Подходы

**Один проход.** Поддерживаются две строки: максимальная `largest` и вторая максимальная `second_largest`. При обнаружении строки больше текущего максимума прежний максимум становится вторым. Иначе строка-кандидат обновляет второй максимум, только если она отличается от первого и больше текущего второго максимума. Повтор максимума не должен занимать второе место.

**Сортировка.** Строки помещаются в массив и сортируются по возрастанию. Затем выполняется проход с конца: первое значение, отличное от максимального, и является ответом. Если такого значения нет, возвращается `NONE`.

### 5.3. Сложность

Пусть `n` — количество строк, `L` — максимальная длина строки, а `C` — стоимость одного сравнения строк, в худшем случае `O(L)`.

| Подход | Время | Дополнительная память |
|---|---|---|
| Один проход | `O(nL)` в худшем случае | `O(L)` для хранимых строк и текущей строки, без учёта входного потока |
| Сортировка | `O(n log n · L)` в худшем случае | `O(nL)` для хранения строк |

Однопроходный алгоритм хранит лишь несколько строк, поэтому экономнее по памяти. Сортировка проще для последующего анализа всего набора, но требует хранения всех строк и выполняет больше сравнений.

### 5.4. Тесты

| Входные строки | Ожидаемый результат | Что проверяется |
|---|---|---|
| `apple, banana, cherry, date, elderberry` | `date` | Пример из задания |
| `apple` | `NONE` | Одна строка |
| `pear, pear, pear` | `NONE` | Все значения равны |
| `pear, pear, apple` | `apple` | Повтор максимума |
| `apple, apples, apricot` | `apples` | Общий префикс |
| `a, c, b, c` | `b` | Повтор максимума и порядок |

Фактические результаты следует записать после запуска обоих вариантов на одном и том же наборе тестов. Для каждого теста проверяется, что ответ меньше максимума и между ними нет другой различной строки.

## 6. Задание 4. Проверка строки на палиндром

### 6.1. Контракт

Вводится одна строка ASCII длиной до `100000` символов. Учитываются только латинские буквы и цифры; регистр букв игнорируется. Пробелы и остальные символы пропускаются. Пустая строка или строка без букв и цифр считается палиндромом. Результат — `YES` или `NO`.

### 6.2. Подходы

**С очищенной строкой.** Создаётся новая строка, в которую записываются только буквы и цифры в нижнем регистре. Затем сравниваются симметричные символы с двух концов.

**Без копии.** Два индекса двигаются от начала и конца исходной строки. Каждый индекс пропускает символы, которые не являются буквами или цифрами. После этого символы сравниваются без учёта регистра. При несовпадении возвращается `false`.

При использовании функций `<cctype>` символ предварительно преобразуется к `unsigned char`, что исключает неопределённое поведение для отрицательных значений типа `char`.

### 6.3. Сложность

Пусть `L` — длина исходной строки.

| Подход | Время, худший случай | Дополнительная память |
|---|---|---|
| Очищенная строка | `O(L)` | `O(L)` |
| Два указателя по исходной строке | `O(L)` | `O(1)` |

Оба алгоритма просматривают строку линейное число раз. Первый хранит очищенную копию, второй использует только индексы и временные значения, поэтому требует константную дополнительную память.

### 6.4. Тесты

| Исходная строка | Ожидаемый результат |
|---|---|
| `A man, a plan, a canal, Panama` | `YES` |
| Пустая строка | `YES` |
| `!!!` | `YES` |
| `0P` | `NO` |
| `AbBa` | `YES` |
| `ab ca` | `NO` |
| `No 'x' in Nixon` | `YES` |

Нужно проверить, что оба подхода дают одинаковые результаты на всех строках, включая пустую строку и строку, состоящую только из знаков пунктуации.

## 7. Задание 5. Количество различных элементов

### 7.1. Контракт

На вход поступает массив из `0 <= n <= 100000` целых чисел. Необходимо вывести количество различных значений. Повторяющееся значение учитывается один раз, даже если встречается много раз. Это не то же самое, что количество элементов, встретившихся ровно один раз.

### 7.2. Подходы

**Полный перебор.** Для каждого элемента проверяется, встречался ли он ранее. Если совпадений среди предыдущих элементов нет, счётчик различных значений увеличивается. Этот вариант подходит для небольших `n` (по условию эксперимента — до 2000).

**Сортировка.** Массив сортируется, затем подсчитываются изменения между соседними элементами. В реализации сортировка меняет исходный массив.

**Хеш-таблица.** Элементы вставляются в `std::unordered_set`; размер множества равен количеству различных значений. Исходный массив при этом не изменяется.

### 7.3. Сложность

| Подход | Время | Дополнительная память | Изменяет вход |
|---|---|---|---|
| Полный перебор | `O(n²)` в худшем случае | `O(1)` | Нет |
| Сортировка | `O(n log n)` | Зависит от реализации сортировки; вход сортируется на месте | Да |
| `unordered_set` | `O(n)` ожидаемо; `O(n²)` в худшем случае | `O(n)` | Нет |

Хеш-таблица обычно эффективна для больших массивов, но требует дополнительной памяти и её линейная оценка является ожидаемой, а не гарантированной для худшего случая. Сортировка удобна, если изменение входа допустимо или копия уже имеется. Если исходный массив нельзя изменять, можно использовать хеш-таблицу либо отсортировать отдельную копию, учитывая её память.

### 7.4. Тесты

| Массив | Ожидаемый результат |
|---|---:|
| `[]` | `0` |
| `[9]` | `1` |
| `[4, 4, 4, 4]` | `1` |
| `[-1, 0, -1, 2]` | `3` |
| `[5, 4, 3, 2, 1]` | `5` |
| `[1, 2, 1, 2, 3, 3]` | `3` |

Все три алгоритма должны возвращать одинаковый результат. Для полного перебора необходимо соблюдать ограничение `n <= 2000`, а быстрые варианты проверить также на `n = 100000`.

## 8. Задание 6. Первое отсутствующее положительное число

### 8.1. Контракт

Дан массив целых чисел длины `0 <= n <= 100000`. Требуется найти наименьшее положительное целое число, отсутствующее в массиве. Нули, отрицательные значения и повторы не меняют смысл задачи.

### 8.2. Подходы

**Полный перебор.** Начинаем с кандидата `1`. Для каждого кандидата выполняется поиск по массиву. Если значение найдено, кандидат увеличивается; первый ненайденный кандидат является ответом. Реализация использует `std::count`, поэтому каждый такой поиск выполняет полный проход по диапазону.

**Массив отметок.** Ответ обязательно находится в диапазоне от `1` до `n + 1`: массив из `n` элементов не может содержать все `n + 1` различных чисел `1, 2, ..., n + 1`. Создаётся массив отметок размера `n + 2`. Для каждого входного значения проверяется, лежит ли оно в диапазоне `[1, n + 1]`, и только затем используется как индекс. После заполнения возвращается первая неотмеченная позиция.

**Хеш-таблица.** В множество помещаются положительные значения, не превышающие `n + 1`. Затем кандидаты от `1` до `n + 1` проверяются по очереди. Этот вариант имеет ожидаемое линейное время, но использует дополнительную память.

### 8.3. Сложность

| Подход | Время | Дополнительная память |
|---|---|---|
| Полный перебор | `O(n²)` в худшем случае | `O(1)` |
| Массив отметок | `O(n)` | `O(n)` |
| Хеш-таблица | `O(n)` ожидаемо, до `O(n²)` в худшем случае | `O(n)` |

Для полного перебора каждый кандидат требует прохода по массиву, а число кандидатов может быть порядка `n`. Массив отметок даёт линейное решение с предсказуемой памятью. Хеш-таблица также ожидаемо линейна, но имеет накладные расходы на хранение узлов и хеширование.

### 8.4. Тесты

| Массив | Ожидаемый результат |
|---|---:|
| `[]` | `1` |
| `[-3, -1, 0]` | `1` |
| `[1, 1, 2]` | `3` |
| `[3, 4, -1, 1]` | `2` |
| `[1, 2, 3, 4]` | `5` |
| `[1000000000]` | `1` |
| `[2, 2, 0, -4]` | `1` |

Перед использованием значения как индекса необходимо проверять его диапазон. Для варианта с отметками достаточно памяти порядка `n`, а не максимального значения элемента массива.

## 9. Общие выводы

В ходе работы рассматриваются базовые алгоритмы линейного просмотра, сортировки, обработки строк и хранения уже встреченных значений. Для поиска максимума и вычисления суммы требуется линейное время и постоянная дополнительная память. Линейный поиск может завершиться раньше, если совпадение найдено в начале массива.

Пузырьковая сортировка с досрочным завершением и сортировка вставками имеют квадратичную худшую сложность, но ведут себя лучше на уже упорядоченных данных. Поэтому при сравнении алгоритмов важно анализировать не только асимптотику, но и фактическое количество сравнений и записей.

Для задачи о второй строке однопроходный алгоритм экономит память по сравнению с сортировкой всех строк. Для палиндрома два указателя позволяют избежать создания дополнительной строки. Для подсчёта различных значений выбор между перебором, сортировкой и хеш-таблицей зависит от размера входа, допустимости изменения массива и доступной памяти. В задаче о первом отсутствующем положительном числе ограничение ответа значением `n + 1` позволяет избежать выделения памяти по максимальному значению исходных данных.
